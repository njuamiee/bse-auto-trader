# bse-auto-trader

北交所智能选股与自动化交易系统的 **MoonBit 核心引擎**。

每天收盘后，引擎跑完"取数 → 算因子 → 打分 → 排序选股 → 风控 → 定仓位 → 生成下单指令 → 逐日记账"这条链路，第二天开盘按指令成交。信号层与执行层分离：选股结果直接产出一张可以交给交易员或券商接口的下单指令表，而不是一堆分数。

整个引擎 100% 用 MoonBit 写成，没有 Python、没有模型文件、没有外部依赖。

## 为什么要写成 MoonBit

因子计算、IC 加权、选股和风控规则都是纯数值与纯规则的工作：没有 I/O、没有随机数、不依赖时钟。这类代码是强类型系统最能发挥价值的地方——同样的输入永远得到同样的输出，可以逐日复盘、可以审计。MoonBit 的多后端（Wasm/JS/Native/LLVM）也让这套核心将来有可能编译成 Wasm，搬到更靠近交易柜台的地方去跑。

## 快速开始

安装 [MoonBit 工具链](https://www.moonbitlang.com/download)（本仓库用 `moon 0.1.20261020` 开发验证）：

```bash
moon version
moon test          # 46 个单元测试
moon run cmd/main  # 12 个交易日的端到端模拟
```

不需要任何本地数据、不需要联网。仓库自带合成行情，任何人 clone 后都能一键复现同样输出。

## 模块

| 文件 | 职责 |
| --- | --- |
| `factors.mbt` | 截面统计：均值、样本标准差、去极值、标准化、Pearson、平均秩、Spearman |
| `weights.mbt` | `DaySlice` / `Feature`、逐日 IC、IC 序列、ICIR、权重归一、复合打分 |
| `select.mbt` | Top-N 选股，并列时取靠前索引保证确定性 |
| `market.mbt` | 每日行情切片（开盘/收盘/可交易/市场广度） |
| `risk.mbt` | 个股止损、账户回撤暂停、市场广度开关、HMM 状态持仓上限 |
| `portfolio.mbt` | 买卖方向、整手取整、现金与单票权重约束、指令文件渲染 |
| `accounting.mbt` | 逐日盯市、资金曲线、总收益、最大回撤、水下天数 |
| `cmd/main/main.mbt` | 12 日端到端模拟 |

## 设计取舍

- **IC 用秩相关而不是 Pearson**：因子尾巴很重，一个极端值不该决定"这个因子像不像有预测力"，所以用 Spearman。
- **先去极值再标准化**：截断带是同一个截面的均值 ± k 倍标准差，顺序写死在 `winsorize_zscore` 里。
- **噪声地板**：一串相同的小数在二进制浮点里并不严格相等，标准差会落在 1e-17 量级，一除就炸。z-score 与 ICIR 都把 1e-12 以下的离散当作零。这个缺陷是被一个失败的测试逼出来的，不是读代码看出来的。
- **风控是状态机，不是开关**：回撤触及阈值立刻停新开仓；停仓期间市场广度要连续 N 天达标才重新开闸，避免一次反弹就把引擎打开。
- **确定性优先**：并列分数取靠前索引，指令顺序不依赖哈希顺序，同一份输入永远给出同一张指令表。
- **实盘语义**：信号只用前一交易日收盘前可得的信息；指令在次日开盘成交；持有满一个周期、跌破止损、掉出目标名单，都在次日开盘平掉。

## 关于数据

模拟用的 12 天价格是**合成数据**。它们的作用是证明整条链路可运行、可复现，不构成任何收益声明。真实运行中，行情、因子与 HMM 状态由数据管线喂进来，换手率需要成交量数据——演示里的换手率是标注清楚的占位值。
