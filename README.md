# bse-auto-trader

北交所智能选股与自动化交易系统的 **MoonBit 核心引擎**。

每天收盘后，引擎跑完"取数 → 算因子 → 打分 → 排序选股 → 风控 → 定仓位 → 生成下单指令 → 逐日记账"这条链路，第二天开盘按指令成交。信号层与执行层分离：选股结果直接产出一张可以交给交易员或券商接口的下单指令表，而不是一堆分数。

整个引擎 100% 用 MoonBit 写成，没有 Python、没有模型文件、没有外部依赖。

## 为什么要写成 MoonBit

因子计算、IC 加权、选股和风控规则都是纯数值与纯规则的工作：没有 I/O、没有随机数、不依赖时钟。这类代码是强类型系统最能发挥价值的地方——同样的输入永远得到同样的输出，可以逐日复盘、可以审计。MoonBit 的多后端（Wasm/JS/Native/LLVM）也让这套核心将来有可能编译成 Wasm，搬到更靠近交易柜台的地方去跑。

## 快速开始

安装 [MoonBit 工具链](https://www.moonbitlang.com/download)（本仓库用 `moon 0.1.20261020` 开发验证）：

```bash
moon version
moon test            # 146 个单元测试
moon run cmd/main    # 12 个交易日的端到端模拟
moon run cmd/verify  # 打印全链路中间值，供外部参照实现逐值比对
moon run cmd/backtest # 解析一张价格表，跑完整回测并给出归因
```

不需要任何本地数据、不需要联网。仓库自带合成行情，任何人 clone 后都能一键复现同样输出。

## 模块

| 文件 | 职责 |
| --- | --- |
| `factors.mbt` | 截面统计：均值、样本标准差、去极值、标准化、Pearson、平均秩、Spearman |
| `weights.mbt` | `DaySlice` / `Feature`、逐日 IC、IC 序列、ICIR、权重归一、复合打分 |
| `select.mbt` | Top-N 选股，并列时取靠前索引保证确定性 |
| `market.mbt` | 每日行情切片（开盘/收盘/可交易/市场广度） |
| `risk.mbt` | 个股止损、账户回撤暂停、市场广度开关、市场状态持仓上限 |
| `portfolio.mbt` | 买卖方向、整手取整、现金与单票权重约束、指令文件渲染 |
| `accounting.mbt` | 逐日盯市、资金曲线、总收益、最大回撤、水下天数 |
| `pipeline.mbt` | 因子构建（动量 / 换手 / 波动 / 前瞻收益）与权重窗口切片，演示与校验共用 |
| `csv.mbt` | 零依赖 CSV 解析：引号转义、CRLF、缺失值一律记为"缺失"而不是 0 |
| `dataset.mbt` | 长表透视：把 `(日期, 代码, 收盘, 成交量)` 行转成"日期 × 标的"矩阵 |
| `tradable.mbt` | 可交易判断：停牌、涨停买不进、跌停卖不出 |
| `settlement.mbt` | 持仓账本：T+1 不可当日回转、先进先出减持 |
| `costs.mbt` | 交易成本：佣金含下限、印花税仅卖出单边、过户费、基点滑点 |
| `metrics.mbt` | 夏普、卡玛、年化波动、胜率、最差单期 |
| `benchmark.mbt` | 每日再平衡等权篮子与超额收益、跟踪误差、信息比率 |
| `attribution.mbt` | 最大回撤起止与是否修复，个券贡献拆解 |
| `walkforward.mbt` | 滚动多折切分，训练与评价之间留出禁运间隔 |
| `cmd/main/main.mbt` | 12 日端到端模拟 |
| `cmd/verify/main.mbt` | 全链路中间值诊断输出（`SCALAR` / `SERIES` / `CODE` 行） |
| `cmd/backtest/main.mbt` | 吃一张价格表，跑完整回测并输出指标、基准对照与归因 |

## 设计取舍

- **IC 用秩相关而不是 Pearson**：因子尾巴很重，一个极端值不该决定"这个因子像不像有预测力"，所以用 Spearman。
- **先去极值再标准化**：截断带是同一个截面的均值 ± k 倍标准差，顺序写死在 `winsorize_zscore` 里。
- **噪声地板**：一串相同的小数在二进制浮点里并不严格相等，标准差会落在 1e-17 量级，一除就炸。z-score 与 ICIR 都把 1e-12 以下的离散当作零。这个缺陷是被一个失败的测试逼出来的，不是读代码看出来的。
- **风控是状态机，不是开关**：回撤触及阈值立刻停新开仓；停仓期间市场广度要连续 N 天达标才重新开闸，避免一次反弹就把引擎打开。
- **确定性优先**：并列分数取靠前索引，指令顺序不依赖哈希顺序，同一份输入永远给出同一张指令表。
- **合成数据刻意不带漂移**：随机步长以零为中心。带哪怕一点点正漂移，随机游走都会变成连年复利，从而虚假地美化每一个策略——这会让夏普和卡玛都变得毫无意义。
- **交易所约束先记账**：一下单就付佣金、过户费与滑点，卖出再付印花税；当天买入的股票当天不许卖；涨停买不进、跌停卖不出。这四条少任何一条，回测都会偏向乐观。
- **实盘语义**：信号只用前一交易日收盘前可得的信息；指令在次日开盘成交；持有满一个周期、跌破止损、掉出目标名单，都在次日开盘平掉。

## 关于数据

演示与回测用的价格是**确定性生成的合成数据**，作用是证明整条链路可运行、可复现，**不构成任何收益声明**。真实运行中，行情、因子与市场状态由数据管线喂进来。

一个诚实的已知限制：**本机 MoonBit 工具链的 core 不含文件系统包**，所以 `cmd/backtest` 接收的是已经在手边的价格表文本，而不是从磁盘读文件。一旦有可用的 FS 接口，替换那几行即可，其余通路完全不变。

`cmd/backtest` 在随机数据上的典型结果，是策略总收益略低于每日再平衡的等权篮子——这正是随机行走上应有的样子。任何声称合成数据能稳定跑出超额的东西，都该被怀疑。

## 与 Python 侧的一致性校验

研究的另一端（数据管道、模型训练、回测）在 Python 仓库里。为了证明 MoonBit 引擎没有把口径算错，另写了一份**独立的 Python 参照实现**（按同一份规格重写，不是翻译 MoonBit 代码），让两边在同一份写死的数据上逐值比对：

```
moon run cmd/verify   # MoonBit 侧打印全链路中间值
python tools/bse_crosscheck/run_crosscheck.py   # 在 Python 仓库里跑
```

当前结果：**81 个中间值，通过 81，失败 0**，容差 1e-9。比对覆盖因子、去极值、标准化、秩 IC、ICIR、权重、复合分、Top-N 选股、整手取整与全部评价指标。

**边界说明**：HMM 的拟合与状态概率更新在 Python 侧完成，MoonBit 只消费已算好的状态标签（`Regime`），本仓库不含模型训练代码。一致性目前只验证到数值层面，不构成任何收益声明。

## 关于这个项目要长成什么样

官方 FAQ 有一句话是这套引擎的设计准则："比起堆叠功能，我们更看重清晰边界、可靠测试、完整文档和真实可用性。"所以这里的扩展是克制的：每个新模块都对应一个会让回测失真的具体风险——免费交易、当天回转、停牌涨停、没有基准——而不是为了看起来更高级。
